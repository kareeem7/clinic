# الإطلاق المجاني — الدليل العملي خطوة بخطوة

> **الهدف:** موقع شغّال على دومين حقيقي، بتكلفة **صفر جنيه**، في حوالي **٩٠ دقيقة**.
> **متى تترقّى:** أول ما تدخل أول مريض ببيانات حقيقية (انظر §٦.١ في `GO_LIVE_PLAN_AR.md`).

---

## ١. الحزمة الجاهزة في المستودع

جهّزت الملفات دي فعليًا، ومحتاجة منك بس الربط:

| الملف | الوظيفة |
| --- | --- |
| `wrangler.toml` | يخلي Cloudflare Pages يفهم إن مفيش build (`command = ""`, `publish_directory = "./"`) |
| `_headers` | رؤوس أمان + سياسة كاش (HSTS، `X-Frame-Options`, `nosniff`) |
| `_redirects` | ٢٠٠ صفحة → مفيش، اختياري — الملف موجود للتوسع |
| `.cfignore` | يمنع نشر `tests/`, `sql/`, `supabase/`, `docs/`, `scripts/` |
| `robots.txt` | يمنع فهرسة `reset.html` وملفات التشغيل |
| `.github/workflows/test.yml` | **CI**: فحص صياغة كل JS + `npm test` (١٩٧ اختبار) + منع تسريب `service_role` |
| `.github/workflows/backup.yml` | **نسخة احتياطية ليلية** `pg_dump` — بديل النسخ الغائب في الخطة المجانية |
| `.github/workflows/keepalive.yml` | **ping كل ٨ ساعات** يمنع توقف المشروع المجاني |
| `scripts/restore.sh` | سكربت استرجاع — لأن نسخة ما اتجرّبتش = مفيش نسخة |

## ٢. اختيار الاستضافة — المقارنة

| المنصة | باندويدث مجاني | دومين مخصص + SSL | build | الحكم |
| --- | --- | --- | --- | --- |
| **Cloudflare Pages** | **غير محدود** | ✅ مجاني | لا يحتاج | 🥇 **الاختيار** |
| GitHub Pages | ١٠٠ جيجا/شهر | ✅ | لا يحتاج | 🥈 بديل ممتاز، لكن النشر من المستودع العام |
| Netlify | ١٠٠ جيجا/شهر | ✅ | لا يحتاج | 🥉 كويس، الحد أضيق |
| Vercel | ١٠٠ جيجا | ✅ | لا يحتاج | مناسب، لكن مخصص للتطبيقات المبنية |

**ليه Cloudflare Pages؟**
1. **الباندويدث غير محدود على الخطة المجانية** — الموقع مش هيتوقف لو زار عليه ناس كتير.
2. **مفيش build** — المشروع HTML/CSS/JS صرف، فالنشر = رفع الملفات.
3. **٢× ٥٠٠ build شهريًا** أكثر من كفاية.
4. **حد ٢٠,٠٠٠ ملف / ٢٥ ميجا للملف** — إحنا عندنا ~٦٠ ملف و١.٣ ميجا إجمالي.
5. DNS نفسه على Cloudflare = الدومين والاستضافة في مكان واحد.

> ⚠️ **مهم:** Cloudflare Pages بيخدم **الملفات الثابتة** مجانًا. متستخدمش **Pages Functions** — كل منطقك على Supabase بالفعل، فمش محتاجها. حط في اعتبارك إن `js/config.js` (١٢٩ كيلو) بيتحمّل مع كل زيارة — مقبول دلوقتي، ونقللـه لاحقًا.

## ٣. الخطوات — من الصفر للدومين

### الخطوة ١ — Supabase مجاني (١٥ دقيقة)

1. أنشئ حساب على [supabase.com](https://supabase.com) → **New project**.
2. **Region:** `eu-central-1` (فرانكفورت) — أقرب وأسرع لمصر من أمريكا.
3. **Database password:** خزّنها في مدير كلمات مرور فورًا.
4. بعد الإنشاء: **SQL Editor** → الصق `SUPABASE_SQL` من `js/config.js` → **Run**.
   - ده التثبيت الكامل من الصفر (١٧ جدول + RLS + RPC). ⚠️ **متشغّلش الترحيلات فوقه.**
5. **Project Settings → API**: انسخ `Project URL` و`anon public key`.
6. **Authentication → URL Configuration**: ضع رابط الدومين (هتعرفه من الخطوة ٣) + `https://<domain>/reset.html`.
7. **Authentication → Providers → Email**: للتجربة عطّل **Confirm email** (وإلا التسجيل هيفشل بـ`confirm-email`).

> 💡 **مشروعان مجانيان:** واحد للتجربة/الديمو وواحد احتياطي. الحد ٢ مشاريع نشطة.

### الخطوة ٢ — محدّث `js/config.js` (٥ دقايق)

```js
const supabaseConfig = {
  url: "https://<project-ref>.supabase.co",
  anonKey: "<anon-public-key>"
};
```

⚠️ **متعملش commit لملف فيه مفاتيح مشروع فيه بيانات حقيقية.** للمشروع التجريبي عادي.

### الخطوة ٣ — النشر على Cloudflare Pages (٢٠ دقيقة)

**الطريقة الأسهل (بدون Git):**
1. [dash.cloudflare.com](https://dash.cloudflare.com) → **Workers & Pages → Create → Pages → Upload assets**.
2. اسحب المجلد (بعد استبعاد `tests/`, `sql/`, `supabase/`, `docs/`).
3. **Deploy** → هتاخد رابط `*.pages.dev` فوري.

**الطريقة الأفضل (مع Git = نشر تلقائي):**
1. ارفع المستودع على GitHub (خاص أو عام).
2. Cloudflare → **Pages → Connect to Git** → اختر المستودع.
3. **Build command:** فاضي · **Build output directory:** `/`
4. **Deploy**.

### الخطوة ٤ — الدومين (١٥ دقيقة)

| الخيار | السعر | ملاحظة |
| --- | --- | --- |
| **مجاني تمامًا** | ٠ | استخدم `clinic.pages.dev` — شغّال بـHTTPS |
| دومين `.com` | ~٦٠٠ ج/سنة | الحل الاحترافي |
| `.clinic` / `.care` | ~٨٠٠–١٢٠٠ ج/سنة | أوضح دلاليًا، أغلى |

**مرحلة «صفر جنيه» بجد:** ابدأ بـ`pages.dev`، والدومين بعد أول عيادة بتدفع.

### الخطوة ٥ — الأسرار في GitHub (١٠ دقايق)

`Settings → Secrets and variables → Actions`:

| السر | القيمة | ليه |
| --- | --- | --- |
| `SUPABASE_DB_URL` | Connection string (URI) من **Database → Connection string** | النسخ الاحتياطي |
| `SUPABASE_URL` | `https://<ref>.supabase.co` | ping |
| `SUPABASE_ANON_KEY` | الـanon key | ping |

⚠️ **متحطّش `service_role` في أي سر يُستخدم في العميل.** سكربت CI بيمنع ده تلقائيًا.

### الخطوة ٦ — تأكيد إن الحاجات شغالة (١٠ دقايق)

- [ ] الموقع يفتح على الرابط
- [ ] تسجيل دكتور جديد يشتغل
- [ ] إنشاء مريض + موعد + ملاحظة
- [ ] بوابة المريض بكود `DEMO1-000001` (لو شغّلت `demo_seed_synthetic.sql`)
- [ ] GitHub Actions → **Tests** ✅ خضراء
- [ ] GitHub Actions → **Nightly backup** → **Run workflow** يدويًا → الـartifact موجود
- [ ] **جرّب الاسترجاع فعليًا** على مشروع staging: `./scripts/restore.sh clinic-*.dump "<staging-url>"`
- [ ] استعادة كلمة المرور: جرّبها ببريد حقيقي

## ٤. إجمالي التكلفة

| البند | التكلفة |
| --- | --- |
| Supabase Free | ٠ |
| Cloudflare Pages | ٠ |
| GitHub Actions | ٠ (٢٠٠٠ دقيقة/شهر في المستودع الخاص) |
| دومين | ٠ لو `pages.dev` · ~٦٠٠ ج/سنة لو مخصص |

**قيود لازم تعيش معاها في الفترة المجانية:**
- المشروع بيتوقف بعد ٧ أيام خمول → `keepalive.yml` بيحلها.
- **صفر نسخ احتياطي** → `backup.yml` بيحلها (٩٠ يوم احتفاظ).
- ٥٠٠ ميجا قاعدة / **١ جيجا ملفات** → الصور هي الخطر، راجع §٦.١.
- سجل أخطاء يوم واحد فقط → راجع `audit_logs` يوميًا.

## ٦. تحذير أخير

الإطلاق المجاني **مناسب للديمو والتجربة والعيادة الأولى المحدودة**، ومش مناسب للتوسع ولا لبيانات مرضى كتير. السبب مش الفلوس — السبب إن **غياب النسخ الاحتياطي المُدار وأمان بوابة المريض** مسؤوليات مالك المشروع، مش مسؤولية المنصة. جهّزت الأدوات، لكن **التشغيل** مسؤوليتك.
