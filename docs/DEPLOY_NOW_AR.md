# من المفاتيح للنشر — الجزء ب من يوم ١

عندك `Project URL` والمفتاح العام. الباقي **٢٠ دقيقة**.

---

## ⚠️ قبل ما تبدأ — قاعدة واحدة

**متلصقش المفاتيح هنا في المحادثة.** مفيش داعي — مفيش حاجة محتاجة سرية، وأنا بعمل الأداة اللي بتظبطهم عندك.

الـ`anon` مش سر بطبيعته، بس مفيش فايدة من مشاركته، ولو غلطت ونسخت `service_role` بالغلط هيكون في سجل المحادثة.

---

## الخطوة ١ — حط المفاتيح (دقيقة)

من جهازك، في مجلد المشروع:

```bash
./scripts/set-keys.sh "https://xxxxxxxx.supabase.co" "sb_publishable_xxxxx"
```

### الأداة دي بتعمل إيه
- ✅ تفحص الـURL (ترفض `https://x` ناقص، أو `/rest/v1` في الآخر)
- ✅ **تفك المفتاح وتقرأ دوره** — لو `service_role` ترفض فورًا
- ✅ تكتب في `js/config.js` وتحتفظ بنسخة احتياطية
- ✅ تتحقق إن الملف لسه سليم (`node --check`) — ولو اتكسر ترجّع النسخة القديمة

### اللي هتشوفه لو نجحت
```
✅ مفتاح publishable (الشكل الجديد)
تم التحديث
✅ صياغة الملف سليمة
✅ تم الربط بمشروع: https://xxxxxxxx.supabase.co
```

### اللي هتشوفه لو المفتاح سري
```
❌❌ ده مفتاح service_role — بيلف حول كل قواعد الحماية.
    لو حطيته، أي زائر يقرأ كل بيانات المرضى. تم الإلغاء.
```
لو ظهر ده → ارجع للوحة Supabase وانسخ المفتاح اللي **اسمه anon أو publishable**، مش اللي اسمه `service_role` أو `secret`.

---

## الخطوة ٢ — فحص وبِناء (دقيقتين)

```bash
./scripts/preflight.sh     # لازم 🟢
./scripts/build-dist.sh    # يطلع مجلد deploy/
```

`preflight` لازم يطبع في الآخر:

```
✅ مشروع Supabase مضبوط: https://xxxxxxxx.supabase.co…
🟢 جاهز للنشر
```

> لو طبع ⚠️ «الوضع التجريبي» يبقى المفاتيح ما اتكتبتش — أعد الخطوة ١.

---

## الخطوة ٣ — النشر على Cloudflare (١٠ دقايق)

1. افتح [dash.cloudflare.com](https://dash.cloudflare.com) — حساب مجاني **بدون بطاقة**
2. **Workers & Pages** → **Create** → تبويب **Pages** → **Upload assets**
3. اسم المشروع: `clinic` (هيبقى `clinic.pages.dev`)
4. **اسحب محتوى مجلد `deploy/`** — الملفات نفسها، **مش المجلد**
5. **Deploy site**

⏱️ هتاخد رابط خلال ثواني.

---

## الخطوة ٤ — رجّع للـSupabase (٣ دقايق)

دلوقتي عندك الرابط، محتاج تعرّفه على Supabase:

1. **Authentication** → **URL Configuration**
2. **Site URL** = `https://clinic.pages.dev` (رابطك الفعلي)
3. **Redirect URLs** → **Add URL** → `https://clinic.pages.dev/reset.html`
4. **Save**

> **ليه؟** من غير البند ده، زرار «نسيت كلمة المرور» هيفشل. Supabase بيرفض أي رابط استعادة مش مسجّل عنده.

---

## الخطوة ٥ — الاختبار (٥ دقايق)

افتح الرابط واعمل الآتي **بالترتيب**:

| # | اعمل | المتوقع |
| --- | --- | --- |
| ١ | الموقع يفتح | شاشة دخول **بدون** كلمة «وضع تجريبي» |
| ٢ | سجّل دكتور جديد | يطلب إعداد 2FA |
| ٣ | امسح QR بـGoogle Authenticator | يقبل الكود ويدخلك |
| ٤ | أضف مريض | يظهر في القائمة |
| ٥ | أضف قياس وزن | يتحفظ |

### لو ظهر «وضع تجريبي»
المفاتيح مش متقراية. اضغط `F12` → Console وابعتلي أول خطأ.

### لو الموقع 404
رفعت مجلد `deploy` نفسه بدل محتواه. ارفع الملفات اللي جواه.

## حاجات متعملها

| ❌ | ليه |
| --- | --- |
| تلصق المفاتيح في المحادثة | مفيش داعي، والأداة بتعملها أحسن |
| تحط `service_role` | كارثة صامتة — متحسش بيها |
| ترفع مجلد `tests/` أو `sql/` | `build-dist.sh` مستبعدهم |
| تفتح «بوابة المريض» | لسه مؤجلة بقرار — متدوسش زرار إصدار الكود |
