# إزاي تجيب المفتاح العام (anon / publishable key)

> **تحذير مهم:** Supabase غيّر اللوحة في نوفمبر ٢٠٢٥. أي شرح قديم (أو فيديو على يوتيوب) بيقولك **Settings → API** — **الصفحة دي مش موجودة خلاص**. هتلفّ عليها ومش هتلاقيها.

---

## المكان الصح

افتح مشروعك → **Settings** (الترس) → **API Keys**

ودوّر على واحد من دول:

| لو المشروع جديد (اتعمل من نوفمبر ٢٠٢٥) | لو المشروع قديم |
| --- | --- |
| مفتاح اسمه **publishable** | مفتاح اسمه **anon** |
| شكله: `sb_publishable_AbC123...` | شكله: `eyJhbGciOiJIUzI1NiIsInR5cCI6...` (طويل جدًا) |
| قصير نسبيًا (~٤٠ حرف) | طويل (~٢٠٠+ حرف) |

**الاتنين شغالين مع مشروعنا** — الكود مش بيفك تشفير المفتاح، فالشكل الجديد هيمشي عادي. ✅

> **تحققت بنفسي:** نسخة المكتبة اللي إحنا مستخدمينها (`@supabase/supabase-js@2.118.0`) فيها دعم صريح لـ`sb_publishable_`. فلو مفتاحك بالشكل الجديد، تمام.

---

## طريقة أسرع — زرار Connect

جوه المشروع، فوق خالص، فيه زرار اسمه **Connect**:

1. اضغط **Connect**
2. هيظهر لك قائمة فيها **App Frameworks**
3. هتلاقي `Project URL` والمفتاح العام جاهزين للنسخ

ده أسرع طريق، وبيشتغل في كل أنواع المشاريع.

---

## إزاي تتأكد إنك أخدت المفتاح **الصح** مش السري

دي أهم نقطة. في نفس الصفحة فيه مفتاح تاني **خطر**:

| المفتاح | شكله | آمن؟ |
| --- | --- | --- |
| **publishable** / **anon** | `sb_publishable_…` أو `eyJ…` | ✅ **آمن** — ده اللي عايزينه |
| **secret** / **service_role** | `sb_secret_…` أو `eyJ…` | ❌ **خطر** — بيفتح كل البيانات |

### لو مفتاحك بالشكل القديم (`eyJ…`) — إزاي تفرّق بينهم

عندك طريقتين:

**١. اللوحة بتقولك:** المفتاح المسموح بيبقى **ظاهر بالكامل**، والسري بيبقى **مخفي ورا نقط** أو ورا زرار `Reveal`. لو القيمة ظاهرة من غير ما تضغط حاجة → ده المفتاح العام.

**٢. افك المفتاح بنفسك** (لو حابب تتأكد ١٠٠٪):
- افتح [jwt.io](https://jwt.io)
- الصق المفتاح في خانة **Encoded**
- بص على `"role"` في الجزء اليمين:
  - `"anon"` → ✅ تمام، كمّل
  - `"service_role"` → ❌ **قف** — ده المفتاح السري، متحطهوش في الموقع أبدًا

> المفتاح `service_role` بيلف حول كل قواعد الحماية (RLS). لو حطيته في الموقع، **أي زائر يقدر يقرأ كل بيانات المرضى**. الـCI عندنا بيمنع ده تلقائيًا.

---

## الشكل النهائي اللي هتلصقه في `js/config.js`

```js
const supabaseConfig = {
  url: "https://xxxxxxxxxxxx.supabase.co",   // Project URL
  anonKey: "sb_publishable_xxxxxxxxxxxx"     // أو eyJhbGciOi...
};
```

### قواعد النسخ
- ✅ انسخ **بدون** مسافات في الأول أو الآخر
- ✅ خلّي علامات التنصيص `"` حول القيمة
- ❌ متضيفش `/rest/v1` آخر الـURL — الكود بيضيفها لوحده
- ❌ متحطش المفتاح السري مهما حصل

---

## إزاي تتأكد إن كل حاجة صح

بعد ما تحط المفاتيح وتنشر:

1. افتح الموقع
2. اضغط `F12` → **Console**
3. لو مفيش أخطاء حمرا → ✅ المفتاح صح
4. لو ظهر `Invalid API key` → المفتاح غلط أو فيه مسافة
5. لو ظهر `Unrecognized Supabase API key format` → **تحذير أصفر بس**، مش خطأ

> **ملاحظة:** لو حطيت `service_role` بالغلط، الموقع هيفتح ويشتغل عادي — **ومش هتحس بفرق**. عشان كده استخدم طريقة `jwt.io` أعلاه لو مش متأكد. الخطأ ده مش بيبان، وأثره كارثي.

---

## لو الصفحة مش زي اللي وصفتها

اللوحة بتتغير. لو مش لاقي **API Keys**:

1. دوّر في القائمة الجانبية على **Project Settings** (مش Settings)
2. أو اكتب في شريط البحث أعلى اللوحة: `API`
3. أو ابعتلي **سكرين شوت** (اخفي المفاتيح منها) وأنا أقولك تضغط فين

---

## الجواب المختصر

> **Settings → API Keys → المفتاح اللي اسمه `publishable` أو `anon`.**
> **الشكل القديم `eyJ`** → افتحه في jwt.io وتأكد إن `"role": "anon"` مش `"service_role"`.
