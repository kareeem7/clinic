# تكلفة الرفع والتشغيل — تقدير واقعي (نوفمبر ٢٠٢٦)

> ملخص سريع: **الموقع "بيتبني" مجانًا تقريبًا، بس تشغيله ببيانات مرضى حقيقية محتاج خطة Supabase مدفوعة (~٢٥ دولار/شهر) لأن الخطة المجانية بتوقف المشروع بعد أسبوع خمول وما فيهاش نسخ احتياطي.**

---

## ١) شكل المشروع التقني (اللي بيحدد التكلفة)

| العنصر | الحالة |
| --- | --- |
| الواجهة | HTML/CSS/JS ثابتة، **بلا build ولا سيرفر** (`index.html` + `css/` + `js/`) |
| الخدمات الخارجية | Supabase (DB + Auth + Storage + Edge Functions)، Font Awesome وChart.js وSupabase JS من CDN |
| عدد جداول القاعدة | ١٧ جدول + عشرات دوال RPC وسياسات RLS |
| Edge Functions | `portal-photo-upload` و`purge-patient-photos` |
| حجم المستودع | ~١.٣ ميجا فقط — لا صور ولا فيديو |
| الاختبارات | `npm test` → **١٩٧ اختبار ناجح / ٠ فاشل** |

الخلاصة: مفيش سيرفر Node ولا Docker ولا قاعدة تديرها بنفسك. التكلفة كلها في **Supabase + الدومين**، وأي حاجة زيادة اختيارية.

## ٢) السيناريوهات والتكلفة الشهرية

أسعار الصرف المستخدمة تقريبية: **١ دولار ≈ ٤٨–٥٠ ج.م** (راجع سعر اليوم قبل الحساب النهائي).

### السيناريو أ — تجربة/ديمو ببيانات وهمية: **٠ ج.م**
- Supabase **Free**: قاعدة ٥٠٠ ميجا، ملفات ١ جيجا، ٥ جيجا خروج بيانات، ٥٠٠ ألف استدعاء Edge Function.
- استضافة الواجهة: **Cloudflare Pages** أو **GitHub Pages** أو **Netlify** — مجانًا تمامًا لموقع ثابت.
- ⚠️ عيوب مقبولة في الديمو فقط: المشروع بيتوقف بعد **٧ أيام خمول**، **ما فيهاش نسخ احتياطي**، وحد أقصى ٢ مشروع نشط.

### السيناريو ب — عيادة واحدة ببيانات مرضى حقيقية: **~١٢٥٠–١٤٠٠ ج.م/شهر (~٢٥–٢٨ دولار)**
| البند | التكلفة |
| --- | --- |
| Supabase **Pro** | **٢٥ دولار/شهر** (شامل ٨ جيجا قاعدة + ١٠٠ جيجا ملفات + ٢٥٠ جيجا خروج + نسخ احتياطي يومي ٧ أيام) |
| دومين (`.com` أو `.clinic`) | ~١٠–١٥ دولار/**سنة** ≈ ٤–٦ ج.م/شهر |
| استضافة الواجهة | ٠ (Cloudflare Pages مجانًا) |
| SMTP للبريد (تأكيد/استعادة كلمة المرور) | ٠ (Resend مجاني حتى ٣٠٠٠ رسالة/شهر) |
| **الإجمالي** | **~٢٥–٢٦ دولار ≈ ١٢٥٠–١٣٠٠ ج.م/شهر** |

> ملاحظة: خطة Pro فيها **١٠ دولار رصيد حوسبة** يغطي مشروع Micro واحد، فالمشروع الأول فعليًا "داخل" الـ٢٥ دولار. أي مشروع إضافي (staging مثلًا) +١٠ دولار/شهر.

### السيناريو ج — لو فعّلت OTP/SMS وإشعارات: **+٥٠٠–١٥٠٠ ج.م/شهر**
| البند | التكلفة التقديرية |
| --- | --- |
| SMS عبر Twilio لمصر | ~٠٫٠٤–٠٫٠٦ دولار للرسالة → ٥٠٠ دخول شهريًا ≈ **٢٥–٣٠ دولار** |
| بديل أرخص: WhatsApp OTP (رسائل Utility) | ~٠٫٠٠٥–٠٫٠١ دولار للرسالة → ٥٠٠ رسالة ≈ **٣–٥ دولار** |
| تسجيل Sender ID في مصر | إجراءات ورقية + تكلفة لمرة واحدة (متغيّرة، تُسأل من المزوّد) |
| إشعارات Push للطبيب (Web Push / OneSignal) | ٠ – ١٠ دولار |

الـOTP **حاليًا مؤجّل** في المشروع، فده مش مصروف إلزامي في اليوم الأول.

### السيناريو د — نمو أكبر (لما تتخطى الحدود)
- قاعدة أكبر من ٨ جيجا: **٠٫١٢٥ دولار/جيجا**.
- خروج بيانات فوق ٢٥٠ جيجا: **٠٫٠٩ دولار/جيجا**.
- ملفات فوق ١٠٠ جيجا: **~٠٫٠٢ دولار/جيجا**.
- ترقية الحوسبة (Small): +١٠ دولار/شهر.
- تقدير عملي: عيادة بـ٢٠٠ مريض شهريًا وصور بحد ٥ ميجا → **أقل بكثير من الحدود**؛ الصور هي اللي هتستهلك الأول، والحل تشغيل دالة `purge-patient-photos` (مسح بعد ٣٠ يوم) وهي **غير منشورة بعد**.

## ٤) هل الموقع جاهز للرفع؟

**الرفع نفسه: نعم.** موقع ثابت + قاعدة Supabase، تقدر ترفعه على Cloudflare Pages في نص ساعة.

**التشغيل ببيانات مرضى حقيقية: لأ، لسه.** الـREADME نفسه بيقول «**غير جاهز لبيانات مرضى حقيقية**»، ودي أسبابي المؤيدة بعد مراجعة الكود:

1. **كود بوابة المريض دائمی ومخزّن كما هو** — ٦ أرقام + رقم الموبايل يفتحوا الملف، ومفيش زر تغيير ولا استرجاع لو الكارت ضاع. أي طرف يقرأ الداتابيز يقدر يدخل كأي مريض.
2. **MFA مش مفعّل فعليًا** — الترحيل موجود لكن لازم تفعيل TOTP لكل حساب قبل تطبيقه.
3. **`purge-patient-photos` غير منشور** — يعني الصور هتتخزن للأبد وتاكل من مساحة الـ١٠٠ جيجا، ومفيش التزام بحذف بعد ٣٠ يوم.
4. **مفيش نسخ احتياطي كامل** — `DB.dumpAll()` ما بيصدّرش `patient_labs` ولا `patient_health_readings` ولا `patient_portal_credentials`، ومفيش مسار استيراد. الخطة المدفوعة بتحل جزء من ده (نسخ يومي ٧ أيام)، والأفضل نسخة خارجية (`pg_dump` على Backblaze B2 ≈ ٦ دولار/تيرا).
5. **مفيش اختبار RLS/RPC على PostgreSQL حقيقي** — الـ١٩٧ اختبار كلها محاكاة DOM/RPC، مش إثبات لعزل البيانات.
6. **`js/config.js` فيه Project URL وanon key مرفوعين في المستودع.** الـanon key عام بطبيعته، لكن لو المشروع ده فيه بيانات حقيقية والمستودع عام، الأنضف تعمل مشروع إنتاج منفصل بمفاتيح جديدة.

## ٥) توصيتي كخطة تنفيذ

**المرحلة ١ (ديمو، دلوقتي، ٠ جنيه):** Supabase Free منفصل + Cloudflare Pages + بيانات `sql/demo_seed_synthetic.sql`. الهدف: العرض على دكاترة وجمع ملاحظات.

**المرحلة ٢ (أول عيادة حقيقية، ~١٢٥٠–١٣٠٠ ج.م/شهر):** Supabase Pro + دومين + إعداد Redirect URLs + نشر `purge-patient-photos` + MFA لكل حساب + نسخة خارجية أسبوعية. وابدأ بمرضى قليلين جدًا وبيانات mínimal.

**المرحلة ٣ (بعد استقرار):** OTP كطبقة فوق الكود (+٣–٣٠ دولار حسب المزوّد) وإشعارات.

**أقل ميزانية واقعية للشهر الأول: ~١٥٠٠ ج.م** (اشتراك + دومين لسنة + احتياطي بسيط).

## ٦) مقارنة سريعة بين البدائل

| الخيار | شهريًا | مناسب لـ |
| --- | --- | --- |
| Supabase Free | ٠ | ديمو فقط (بيتوقف بعد ٧ أيام خمول، بلا باك أب) |

### تنويه قانوني
بيانات المرضى في مصر بتدخل تحت **قانون حماية البيانات الشخصية ١٥١/٢٠٢٠** (بيانات صحية = حساسة). الاستضافة خارج مصر (Supabase في أوروبا/أمريكا) مسموحة بشروط لكن محتاجة تقييم وضوابط وموافقة المريض. خطة Pro **مش HIPAA**؛ Team فيها إضافة HIPAA مدفوعة لو احتجت.

*كل الأرقام تقديرية لشهر نوفمبر ٢٠٢٦ ومبنية على نطاق استخدام عيادة صغيرة (مئات المرضى شهريًا).*
