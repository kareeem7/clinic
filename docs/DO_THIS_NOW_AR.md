# اعمل إيه بالظبط — خطوة بخطوة، بدون terminal

**الوقت:** ٢٥ دقيقة · **هتحتاج:** متصفح + Notepad + الملف `clinic-deploy.zip`

> نسخة من الحزمة موجودة عندك جاهزة: **`clinic-deploy.zip`** (١٩٨ كيلو، ٤٨ ملف).
> موجودة في جذر المشروع بجانب `index.html`.

---

# الجزء ١ — تعديل المفتاح (٧ دقايق)

## الخطوة ١.١ — فك الحزمة

- على ويندوز: كليك يمين على `clinic-deploy.zip` → **Extract All** → **Extract**
- هتطلع مجلد اسمه `clinic-deploy`

## الخطوة ١.٢ — افتح ملف الإعدادات

1. ادخل مجلد `clinic-deploy` → ثم `js`
2. هتلاقي ملف اسمه **`config.js`**
3. كليك يمين عليه → **Open with** → **Notepad**

> ⚠️ **متستخدمش** Word أو WordPad. لازم Notepad أو أي محرر نصوص عادي.

## الخطوة ١.٣ — دور على السطرين

اضغط `Ctrl + F` → اكتب `supabaseConfig` → **Find Next**

هتلاقي آخر الملف (تقريبًا سطر ٢٢) حاجة بالشكل ده:

```js
const supabaseConfig = {
  url: "", // Project URL — لا تضف /rest/v1
  anonKey: ""   // ← anon public key
};
```

**لاحظ:** القيمتين **فاضيتين** في الحزمة دي — ده مقصود، عشان تستبدلهم بمفاتيحك.

## الخطوة ١.٤ — الصق الـ URL

- امسح `""` بعد `url:` وحط رابطك بين علامتي تنصيص:

```js
  url: "https://abcdefgh.supabase.co",
```

**قواعد مهمة:**
| ✅ صح | ❌ غلط |
| --- | --- |
| `https://abcdefgh.supabase.co` | `abcdefgh.supabase.co` (ناقص https) |
| | `https://abcdefgh.supabase.co/` (شرطة زيادة) |
| | `https://abcdefgh.supabase.co/rest/v1` (زيادة) |

## الخطوة ١.٥ — الصق المفتاح

- امسح `""` بعد `anonKey:` وحط مفتاحك:

**لو مفتاحك شكله `sb_publishable_...` (قصير):**

```js
  anonKey: "sb_publishable_AbCdEf123456789"
```

**لو مفتاحك شكله `eyJ...` (طويل جدًا):**

```js
  anonKey: "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpc3MiOiJzdXBhYmFzZSIsInJlZiI6ImFiY2RlZmdoIiwicm9sZSI6ImFub24i..."
```

> ⚠️ **المفتاح طويل جدًا** — لازم يبقى **كله في سطر واحد**. لو Notepad كسّره على سطرين، اضغط `Format → Word Wrap` عشان تشوفه صح، **بس متضغطش Enter جواه**.

## الخطوة ١.٦ — احفظ

`Ctrl + S` → اقفل Notepad

## الخطوة ١.٧ — تأكد إنك محطتش المفتاح السري

**افتح [jwt.io](https://jwt.io) والصق مفتاحك هناك:**

| اللي هتلاقيه | المعنى |
| --- | --- |
| `"role": "anon"` | ✅ تمام |
| `"role": "service_role"` | ❌ **قف فورًا** — ده المفتاح السري |
| مفيش شكل JWT (المفتاح قصير `sb_publishable_`) | ✅ تمام، متكملش الفحص ده |

> **دي أهم خطوة في الصفحة كلها.** لو حطيت `service_role`، الموقع هيشتغل عادي تمامًا وإنت مش هتحس بحاجة — بس أي زائر يقدر يقفل عليك كل بيانات المرضى.

# الجزء ٢ — النشر على Cloudflare (١٠ دقايق)

## الخطوة ٢.١ — حساب

1. افتح [dash.cloudflare.com](https://dash.cloudflare.com/sign-up)
2. اعمل حساب بإيميلك
3. **مش هيطلب بطاقة بنكية** — لو طلب، يبقى إنت في مكان تاني

## الخطوة ٢.٢ — اعمل مشروع

1. من القائمة اليسرى: **Workers & Pages**
2. زرار **Create** (أزرق فوق يمين)
3. في التبويبات: اختار **Pages**
4. اضغط **Upload assets**

## الخطوة ٢.٣ — الاسم

1. **Project name:** اكتب `clinic`
   - ده هيبقى رابطك: `clinic.pages.dev`
   - لو الاسم محجوز، اكتب `clinic-eg` أو أي حاجة
2. **Create project**

## الخطوة ٢.٤ — ارفع الملفات

1. هتلاقي مربع كبير مكتوب فيه **Drag and drop your files here**
2. **افتح** مجلد `clinic-deploy`
3. **حدد كل اللي جواه** (`Ctrl + A`)
4. **اسحبهم** وارميهم في المربع

### ⚠️ أخطر غلطة هنا

| ❌ | ✅ |
| --- | --- |
| تسحب **مجلد** `clinic-deploy` نفسه | تسحب **الملفات اللي جواه** |
| النتيجة: موقع 404 | النتيجة: موقع شغال |

**إزاي تتعرف إنك صح؟** بعد الرفع لازم تشوف في القائمة ملفات اسمها `index.html`, `_headers`, ومجلدين `css`, `js`. لو شفت مجلد واحد اسمه `clinic-deploy` → امسحهم وأعد السحب.

## الخطوة ٢.٥ — انشر

1. اضغط **Deploy site**
2. استنى ١٠–٣٠ ثانية
3. هيظهرلك رابط زي: `https://clinic-abc.pages.dev`
4. **انسخ الرابط ده** وافتحه

# الجزء ٣ — رجّع للـSupabase (٣ دقايق)

## الخطوة ٣.١ — عرّف Supabase بالرابط

1. افتح مشروعك في Supabase
2. **Authentication** (القائمة اليسرى) → **URL Configuration**
3. **Site URL:** الصق رابط Cloudflare
   - `https://clinic-abc.pages.dev`
4. **Redirect URLs** → **Add URL** → الصق:
   - `https://clinic-abc.pages.dev/reset.html`
5. **Save**

> **ليه؟** من غير الخطوة دي، زرار «نسيت كلمة المرور» هيفشل — وهيفشل بصمت من غير رسالة واضحة.

## الخطوة ٣.٢ — تأكد إن Confirm email مقفول

1. **Authentication** → **Providers** → **Email**
2. **Confirm email** لازم يبقى **مقفول** (OFF)

> لو مفعّل، حاجة زي «تسجيل حساب جديد» هترمي `confirm-email` وهتوقف.

# الجزء ٤ — الاختبار (٥ دقايق)

افتح رابطك واعمل ده **بالترتيب**:

| # | اعمل إيه | المفروض يحصل |
| --- | --- | --- |
| ١ | الموقع يفتح | شاشة تسجيل دخول |
| ٢ | بص على تحت الشاشة | **مفيش** كلمة «وضع تجريبي» |
| ٣ | اضغط **حساب جديد** | تظهر خانات التسجيل |
| ٤ | املأ: اسم + تخصص + عيادة + إيميل + باسورد | — |
| ٥ | اضغط تسجيل | يظهر QR code |
| ٦ | نزّل Google Authenticator على موبايلك | — |
| ٧ | امسح الـQR | يظهر كود ٦ أرقام كل ٣٠ ثانية |
| ٨ | اكتب الكود | تدخل لوحة التحكم |
| ٩ | **المرضى** → أضف مريض | يظهر في القائمة |
| ١٠ | افتح ملف المريض → أضف وزن | يتحفظ |

# لو حصلت مشكلة

| اللي بتشوفه | السبب | الحل |
| --- | --- | --- |
| الصفحة بيضا فاضية | رفعت مجلد بدل محتواه | أعد الجزء ٢.٤ — اسحب **الملفات** |
| 404 | نفس السبب فوق | نفس الحل |
| مكتوب «وضع تجريبي» | المفاتيح فاضية أو فيها مسافة | أعد الجزء ١ |
| `Invalid API key` في الـConsole | المفتاح ناقص أو فيه سطر جديد | امسحه والصقه تاني في سطر واحد |
| «تعذر الاتصال» | الـURL فيه `/` زيادة | شيل الشرطة الأخيرة |
| التسجيل يرمي `confirm-email` | التأكيد مفعّل | الجزء ٣.٢ |
| استعادة الباسورد مش بتشتغل | Redirect URL ناقص | الجزء ٣.١ |

`F12` → تبويب **Console** → لون أحمر = خطأ → **صوّر الشاشة** وابعتلي

## ملاحظة أخيرة

الحزمة اللي عندك فيها `js/config.js` **بالقيم فاضية** — مفيش أي مفتاح أو مشروع قديم. ده مقصود: عشان لو نسيت التعديل، تشوف «وضع تجريبي» وتعرف إن فيه حاجة ناقصة، بدل ما الموقع يتصل بمشروع غلط وإنت مش واخد بالك.
