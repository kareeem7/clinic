## ١. ملخص تنفيذي

| السؤال | الجواب |
| --- | --- |
| هل الموقع جاهز للرفع تقنيًا؟ | **نعم** — موقع ثابت بلا build، ينشر في أقل من ساعة |
| هل جاهز لبيانات مرضى حقيقية؟ | **لا** — ٦ بلوكرات أمنية/تشغيلية (تفصيلها في §٣) |

## ٢. الوضع الحالي — ما هو موجود فعلًا

### ✅ جاهز
- واجهة كاملة (٢٣ ملف JS + ١٨ ملف CSS) تعمل بلا build ولا bundler.
- مخطط قاعدة كامل: **١٧ جدول**، سياسات RLS، عشرات دوال RPC، بوابات اشتراك داخل RLS (`clinic_active`).
- بوابة مريض، فروع متعددة، تحاليل، قراءات سكر/ضغط، InBody، واتساب.
- لوحة سوبر أدمن مع تعليق/تفعيل حسابات وإعدادات نظام (`admin_set_doctor_status`, `system_settings`).
- **١٩٧ اختبار ناجح** (`npm test`) — محاكاة DOM/RPC.
- Edge Functions مكتوبة: `portal-photo-upload` + `purge-patient-photos` (غير منشورتين).

### ❌ ناقص (يحدد خطة العمل)
| # | الناقص | الأثر |
| --- | --- | --- |
| 1 | كود المريض **دائم + مخزّن كنص صريح**، بلا زر تغيير | مفيش استرجاع لو الكارت ضاع؛ أي طرف يقرأ DB يدخل كأي مريض |
| 2 | MFA مكتفولة في الكود (`register` → `mfa-enroll`) لكن الترحيل **غير مطبّق** | الحماية معلّقة |
| 3 | `purge-patient-photos` غير منشورة + لا جدولة | الصور تتراكم للأبد |
| 4 | لا نسخة احتياطية كاملة (`dumpAll` ناقص) | لا استرجاع عند تلف البيانات |
| 5 | **لا بوابة دفع** — التفعيل يدوي من السوبر أدمن | نموذج الاشتراك غير قابل للتوسع |
| 6 | لا CI/CD ولا اختبار RLS على Postgres حقيقي | أي تعديل SQL ينشر على العميان |
| 7 | `js/config.js` فيه مفاتيح مشروع تجريبي + لا إعداد Redirect URLs إنتاجي | استعادة كلمة المرور هتفشل |
| 8 | اعتماد على ٣ CDN خارجية (jsdelivr, cdnjs, Google Fonts) | لو اتقطعت → الموقع يقع |

## ٣. البلوكرات الأمنية — تفصيل وطريقة الإغلاق

### 🔴 B1 — كود بوابة المريض (الأخطر)
**الوضع:** `patient_portal_credentials` يخزّن الكود كما هو، ٦ أرقام + رقم موبايل = دخول. مفيش OTP، مفيش تدوير.

**خيارات الإغلاق (اختر واحد):**

| الخيار | التنفيذ | الأثر | الوقت |
| --- | --- | --- | --- |
| **أ. أسرع** | تشفير الأكواد (hashing) + إظهارها من cache آمن لحظة الإصدار فقط + تعويض بكود ٨ خانات | يقفل قراءة DB المباشرة، لكن الدكتور مش هيشوف الكود تاني | ٦–٨ س |
| **ب. متوازن (موصى به)** | كود ٨ خانات + OTP/SMS كطبقة إضافية قبل أول عيادة حقيقية | يحل التخمين والسرقة | ١٦–٢٤ س |
| **ج. أقوى** | كلمة مرور للمريض + reset بموبايل + سجل أجهزة | أمان أعلى، تجربة أثقل على كبار السن | ٢٤–٣٢ س |

> لو هنطلق بمرضى حقيقيين **دلوقتي**، الخيار أ هو الحد الأدنى المقبول قبل أول بيانات.

### 🔴 B2 — MFA غير مطبّق
ترحيل `20261101_require_mfa.sql` يفرض `aal2` على ١٠ جداول + Storage. التطبيق مكتفول بالفعل (`js/main.js` `mfa-enroll`).
**الخطوات:** حصر الحسابات → تفعيل TOTP لكل دكتور → اختبار دخول/استعادة في staging → تطبيق الترحيل → مراقبة ٢٤ س → خطة رجوع (`drop policy require_mfa`).

### 🟠 B3 — تنظيف الصور
نشر `purge-patient-photos` + `[functions.purge-patient-photos] verify_jwt = true` (مضبوط) + Vault secrets (`clinic_project_url`, `clinic_service_role_key`) + `pg_cron` كل ١٥ دقيقة + `pg_net`.

### 🟠 B4 — النسخ الاحتياطي
Supabase Pro = نسخ يومي ٧ أيام (شامل كل الجداول) **+** نسخة خارجية أسبوعية `pg_dump` → Backblaze B2 (٦ دولار/تيرا) **+** بناء مسار استيراد فعلي (مش موجود حاليًا).

### 🟡 B5 — عزل البيانات غير مُختبر على Postgres حقيقي
لا يوجد `pgtap` ولا CI SQL. المطلوب: مشروع staging منفصل + سيناريوهات: دكتور A ما يشوفش B، عيادة موقوفة تفقد الوصول، بوابة المريض ما تقرأش جداول، `anon` ممنوع من `purge_deleted_rows`.

### 🟡 B6 — مفاتيح المشروع في الكود
`js/config.js` سطور ٢٢–٢٣. الإنتاج = مشروع Supabase جديد + مفاتيح جديدة + **عدم** إعادة استخدام مشروع فيه بيانات.

## ٦. الميزانية

### شهرية
| البند | التكلفة |

| Supabase Pro (إنتاج) | ٢٥ $ ≈ ١٢٥٠ ج |
| Supabase staging | ٠ (Free، يوقف بعد ٧ أيام خمول — مقبول) |
| استضافة ثابتة (Cloudflare Pages) | ٠ |
| SMTP (Resend) | ٠ حتى ٣٠٠٠ رسالة |
| دومين | ~٦ ج/شهر (٦٠٠/سنة) |
| **الإجمالي** | **~١٢٥٦ ج.م/شهر** |

### لمرة واحدة
| البند | التكلفة |
| --- | --- |
| دومين سنة | ~٦٠٠ ج |
| بوابة دفع — تأسيس (اختياري) | ١٠٠٠–٢٠٠٠ ج |
| مراجعة أمنية خارجية (اختياري، موصى بها قبل التوسع) | متغيّر |

### حساب التعادل
- إيراد العيادة الواحدة: ٣٠٠ ج/شهر (أو ٣٠٠٠/سنة = ٢٥٠ ج/شهر).
- تكلفة ثابتة: ~١٢٥٦ ج/شهر.
- **التعادل ≈ ٥ عيادات** (شهري) أو **٦ عيادات** (سنوي).
- عند ٢٠ عيادة: إيراد ٦٠٠٠ ج − تكلفة ~١٥٠٠ ج (بعد عمولات الدفع) = **صافي ~١٣٥٠٠ ج/شهر**.

### متى تتغير التكلفة
| الحدث | الزيادة |
| --- | --- |
| قاعدة > ٨ جيجا | ٠٫١٢٥ $/جيجا |
| خروج بيانات > ٢٥٠ جيجا | ٠٫٠٩ $/جيجا |
| صور متراكمة > ١٠٠ جيجا | ٠٫٠٢ $/جيجا — **الحل: تشغيل B3** |
| مشروع إضافي | +١٠ $/شهر |
| OTP لكل ٥٠٠ دخول | ٣–٣٠ $ حسب المزوّد |
